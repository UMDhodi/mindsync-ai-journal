## 📖 Brief Description of What You Have Built

**MindSync AI** is a multi-tenant personal journal, cognitive reframing assistant, and strategic brainstorming platform designed for high-concurrency deployment on **Google Cloud Run**. Rather than acting as a simple text log, MindSync pairs reflective writing with real-time generative intelligence:

1. **Socratic Dialogue & Cognitive Reframing**: An empathetic thinking partner that helps knowledge workers unpack dilemmas, spot hidden assumptions, reframe limiting cognitive distortions (such as false dichotomies or catastrophizing), and uncover clarity.
2. **Dynamic Sentiment & Valence Synthesis**: Automated extraction of emotional valence (-1.0 to +1.0), cognitive energy levels, core themes, and actionable milestones.
3. **Interactive 2D Concept Mind Map**: Transforms unstructured stream-of-consciousness writing into a topological knowledge graph categorizing Core Goals, Challenges, Insights, Action Milestones, and Levers.
4. **Client-Side Zero-Knowledge Cryptographic Vault**: Optional client-side AES-GCM 256-bit encryption (PBKDF2 with 100,000 iterations) ensuring private reflections can never be read by the server or database in cleartext.
5. **Editorial Aesthetics**: Clean typographic hierarchy, rich Markdown rendering, and system-adaptive light/dark themes.

## 🚀 How We Leverage Google Cloud Technologies

### 1. Google Cloud Run
MindSync AI is built to run natively in **Google Cloud Run** containers:
- **Full-Stack Single-Container Architecture**: A unified container hosting an Express.js server on port `3000` that handles both secure `/api/*` routes and static asset delivery generated by Vite.
- **Service Label Compliance**: Tagged with `dev-tutorial=cloud-run-ai-challenge` via deployment flags and verified dynamically on the `/api/health` endpoint.
- **Stateless & Scalable**: Scales to zero when idle and rapidly scales up on concurrent journaling sessions.
- **Secure Server-Side API Gateway**: Protects all AI secrets by brokering requests on Cloud Run. API keys never reach browser bundles.

### 2. Firebase Authentication
- **Multi-Provider Support**: Supports Email/Password, Google OAuth, and Anonymous Guest access.
- **Cryptographic Token Verification**: Every API request sends a Firebase ID token (`Authorization: Bearer <token>`). The Cloud Run server validates the token and extracts the authenticated `req.user.uid`.
- **Tenant Context Extraction**: Establishes strict multi-tenant boundary checks before any database query or AI inference occurs.

### 3. Google Cloud Firestore
- **Strict Hierarchical Multi-Tenancy**: Data is partitioned strictly by user ID:
  - `/users/{userId}/sessions/{sessionId}` — Journaling sessions and metadata.
  - `/users/{userId}/sessions/{sessionId}/messages/{messageId}` — Turn-by-turn reflections and AI reframings.
  - `/users/{userId}/summaries/{summaryId}` — Deep analytical reframings and sentiment valence charts.
  - `/users/{userId}/graphs/{graphId}` — 2D concept mind-map nodes and relational links.
  - `/users/{userId}/audit_logs/{logId}` — Tenant-scoped security and interaction telemetry.
- **Hardened Security Rules (`firestore.rules`)**:
  - Enforces `request.auth.uid == userId` across all read, write, and delete operations.
  - Implements default-deny on all unmapped root collections (`match /{document=**} { allow read, write: if false; }`).
  - Completely prevents cross-tenant data leakage.
- **Optimized Querying**: Configured with compound indexes (`firestore.indexes.json`) for fast chronological retrieval.

### 4. Google Gemini (`@google/genai` TypeScript SDK)
MindSync leverages **Google Gemini 3.8 Flash** through the official Google Gen AI SDK on the Cloud Run backend:
- **Zero-Leakage Architecture**: Secrets are managed securely via environment variables and Google Cloud Secret Manager with in-memory TTL caching.
- **Structured Outputs via JSON Schema (`responseSchema`)**:
  - Predictable extraction of emotional valence, energy score, and structured action steps.
  - Deterministic generation of node-link graph topologies with categorized labels and link strengths.
- **Rich Markdown Formatting**: Answers are structured with bolded terminology, bulleted action items, blockquotes, and code syntax highlighting.
- **Prompt Injection Defense**: Input validation with Zod schemas and pre-execution delimiter scanners mitigate prompt override attempts.

## 🔒 Security & Privacy Engineering

MindSync adheres to enterprise-grade security standards aligned with **STRIDE** and the **OWASP Top 10 for LLMs**:

| Threat Category | Risk Description | MindSync Implementation |
| :--- | :--- | :--- |
| **Spoofing** | Forged user authentication | Firebase JWT tokens cryptographically verified per request; `req.user.uid` strictly enforced. |
| **Tampering** | Modifying other tenants' data | Firestore rules assert `request.auth.uid == userId`. Parameterized queries prevent NoSQL injection. |
| **Repudiation** | Denying interaction history | ISO 8601 server-stamped immutable logs under `/users/{userId}/audit_logs`. |
| **Information Disclosure** | API key leakage to browser | Zero secrets bundled into client code. Keys fetched strictly on server via Secret Manager or AI Studio. |
| **Denial of Service** | Unbounded prompt payloads | Zod schema bounds input length (max 12,000 chars); rate limits on cognitive engine endpoints. |
| **Elevation of Privilege** | Accessing cross-tenant sessions | Hierarchical scoping guarantees `/users/{userId}/*` path boundaries. |
| **LLM01: Prompt Injection** | Adversarial prompt override | Pre-execution heuristic scanner detects delimiter manipulation; system instructions safely isolated. |
| **LLM02: Insecure Output** | Malformed / dangerous AI JSON | Strict typed schemas (`responseSchema`) applied across all cognitive analysis and concept graph calls. |
| **LLM06: Sensitive Data** | Storing PII in plaintext | Client-Side Zero-Knowledge AES-GCM 256-bit vault ensures server never sees cleartext for private sessions. |

## 🛠️ Deploying to Google Cloud Run

Deploy MindSync AI to Google Cloud Run with the required service label:

### Prerequisites
1. Google Cloud SDK (`gcloud`) installed and authenticated.
2. Google Cloud project with billing enabled.
3. Enabled services:
   ```bash
   gcloud services enable run.googleapis.com \
     firestore.googleapis.com \
     secretmanager.googleapis.com \
     artifactregistry.googleapis.com
   ```

### Step 1: Deploy Directly via Cloud Run Source Build
```bash
gcloud run deploy mindsync-ai-journal \
  --source . \
  --region us-central1 \
  --platform managed \
  --allow-unauthenticated \
  --port 3000 \
  --labels dev-tutorial=cloud-run-ai-challenge \
  --set-env-vars="GEMINI_SECRET_NAME=default-ai-studio-api"
```

### Step 2: (Optional) Google Secret Manager Configuration
To manage custom Gemini API keys through Cloud Secret Manager:
```bash
# 1. Create the secret
echo -n "YOUR_GEMINI_API_KEY" | gcloud secrets create gemini-api-key \
  --data-file=- \
  --replication-policy="automatic"

# 2. Grant Cloud Run Service Account access
PROJECT_NUMBER=$(gcloud projects describe $(gcloud config get-value project) --format="value(projectNumber)")
gcloud secrets add-iam-policy-binding gemini-api-key \
  --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"

# 3. Bind secret to Cloud Run
gcloud run services update mindsync-ai-journal \
  --set-secrets="GEMINI_API_KEY=gemini-api-key:latest" \
  --region us-central1
```

## 📡 API Reference Summary

All user-facing endpoints require `Authorization: Bearer <Firebase_ID_Token>`.

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/health` | Public health check returning service label `dev-tutorial=cloud-run-ai-challenge` and runtime status. |
| `GET` | `/api/security/audit` | Retrieves tenant-scoped security metrics, encryption flags, and audit telemetry. |
| `GET` | `/api/sessions` | Lists all journal and brainstorming sessions belonging to the authenticated tenant. |
| `POST` | `/api/sessions` | Creates a new session with optional client-side encryption indicator. |
| `GET` | `/api/sessions/:id` | Retrieves a session and its turn-by-turn message transcript. |
| `POST` | `/api/sessions/:id/messages` | Sends a reflection; generates an interactive Gemini response formatted in Markdown. |
| `POST` | `/api/sessions/:id/analyze` | Generates a structured cognitive reframing report and emotional valence score. |
| `POST` | `/api/sessions/:id/graph` | Synthesizes a 2D topological thought graph (nodes and relational links). |
| `DELETE` | `/api/sessions/:id` | Deletes a session and its associated subcollection documents. |
